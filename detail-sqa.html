Testing — Quality Assurance

Mata kuliah Software Quality Assurance (SQA) mengajarkan kami bahwa menulis kode yang berfungsi baru setengah dari pekerjaan — memastikan kode tersebut benar, andal, dan memenuhi standar kualitas adalah tanggung jawab yang sama pentingnya. SQA adalah disiplin ilmu yang memastikan proses pengembangan perangkat lunak dilakukan secara sistematis dan terstandarisasi.

1. Konsep Dasar Quality Assurance vs Quality Control

Pemahaman pertama yang kami bangun adalah perbedaan mendasar antara dua pendekatan jaminan kualitas:

  • Quality Assurance (QA): Bersifat proaktif. Fokus pada perbaikan proses pengembangan itu sendiri untuk mencegah defect terjadi sejak awal. Contoh: code review wajib, standar penulisan kode, dan checklist sebelum deployment.
  • Quality Control (QC): Bersifat reaktif. Fokus pada pengujian produk akhir untuk mendeteksi dan memperbaiki defect yang telah terjadi. Contoh: pengujian manual, regression testing.

2. Jenis-Jenis Pengujian Perangkat Lunak

Kami mempelajari piramida testing yang komprehensif, dari unit terkecil hingga sistem secara keseluruhan:

  • Unit Testing: Menguji fungsi atau method individual secara terisolasi untuk memastikan setiap unit logika bekerja sesuai spesifikasi.
  • Integration Testing: Menguji interaksi antar modul atau komponen — misalnya, apakah Controller benar-benar memanggil Model dengan parameter yang tepat dan menghasilkan respons yang diharapkan.
  • System Testing: Menguji sistem secara keseluruhan sebagai satu kesatuan untuk memverifikasi bahwa semua persyaratan fungsional terpenuhi.
  • User Acceptance Testing (UAT): Pengujian akhir yang dilakukan oleh pengguna nyata untuk memvalidasi bahwa sistem memenuhi kebutuhan bisnis mereka.
  • Regression Testing: Menjalankan kembali seluruh suite pengujian setelah ada perubahan kode untuk memastikan tidak ada fitur yang sebelumnya berfungsi menjadi rusak.

3. Pengujian Manual: Skenario & Test Case

Kami belajar menyusun dokumentasi pengujian manual yang terstruktur. Setiap Test Case harus memuat:

  • Test Case ID: Identifikasi unik untuk setiap skenario pengujian.
  • Preconditions: Kondisi awal yang harus terpenuhi sebelum pengujian dimulai.
  • Steps to Reproduce: Langkah-langkah tepat dan berurutan untuk mereproduksi skenario.
  • Expected Result: Hasil yang diharapkan jika sistem berfungsi dengan benar.
  • Actual Result: Hasil nyata yang diperoleh saat pengujian dijalankan.
  • Status: PASS atau FAIL berdasarkan perbandingan expected vs actual result.

4. Automated Testing

Pengujian manual tidak efisien untuk diulang setiap kali ada perubahan kode. Kami diperkenalkan pada konsep automated testing menggunakan tools seperti:

  • PHPUnit: Framework pengujian unit yang terintegrasi dengan CodeIgniter 4 untuk menguji logika backend secara otomatis.
  • Selenium / Playwright: Tools untuk end-to-end testing yang mensimulasikan interaksi pengguna nyata di browser secara otomatis.
  • Postman / Newman: Menguji endpoint REST API secara otomatis dan memastikan setiap respons API sesuai kontrak yang didefinisikan.

5. Bug Reporting dan Pelacakan Defect

Ketika defect ditemukan, cara melaporkannya secara efektif sama pentingnya dengan menemukannya. Kami mempelajari cara menulis bug report yang baik menggunakan platform manajemen isu seperti GitHub Issues dan Jira, dengan memastikan setiap laporan mencantumkan langkah reproduksi yang jelas, tingkat keparahan (Severity), dan prioritas penanganan (Priority).

Mata kuliah SQA mengubah cara pandang kami terhadap pengembangan perangkat lunak — kualitas bukan sesuatu yang diperiksa di akhir, melainkan sesuatu yang dibangun sejak awal di setiap tahap pengembangan.
